## 1. What actually exists
- Official [GEMS docs](https://gems-energy.readthedocs.io/en/latest/), [developer guide](https://gems-energy.readthedocs.io/en/latest/support/dev-guidelines/) and [GemsPy docs](https://gemspy.readthedocs.io/en/latest/user-guide/converters/) list forward PyPSA→GEMS and legacy→GEMS. Public reverse-direction search did not identify a dedicated maintained GEMS→PyPSA Network converter. This is limited search evidence, not a proof of nonexistence.
- Reopened pinned [forward register](https://github.com/AntaresSimulatorTeam/PyPSA-to-GEMS-Converter/blob/44d73886cf17040550508e88735e451e59a06d5c/src/pypsa_register.py), [converter](https://github.com/AntaresSimulatorTeam/PyPSA-to-GEMS-Converter/blob/44d73886cf17040550508e88735e451e59a06d5c/src/pypsa_converter.py), [YAML library](https://github.com/AntaresSimulatorTeam/PyPSA-to-GEMS-Converter/blob/44d73886cf17040550508e88735e451e59a06d5c/resources/pypsa_models/pypsa_models.yml). Register maps buses, loads, generators, two-port links, storage units, stores, lines, transformers, two CO2 global constraint senses; forward preprocessing is not injective. No automatic inverse from generated YAML. Converter chooses operational vs investment routing and rejects unequal weights in operative multi-scenario route. Explicit p_min_pu storage discrepancy and omitted transformer phase shift confirmed. B has full negative inventory.
- Reopened [GemsPy optimization.py](https://github.com/AntaresSimulatorTeam/GemsPy/blob/77100798fd4cc7fbb2889fc278b257d58c1f08bb/src/gems_runner/simulation/optimization.py) (blob c8ec3881fc1bdd6ec0dd5cf47874650bb200d554). Source: model-specific arrays on component/time/scenario; vectorized variables, master/slave port aggregation via incidence matrix, AST expression translation; OptimizationProblem stores study/block/linopy_model/variable map, objective constant outside solver, export_lp. DecompositionFilter defaults unspecified elements to subproblems; out-of-bounds filters default cyclic, optional masks. Missing variables on split sides may be treated as zero and nonlinear output-only definitions omitted in LP build. These are execution semantics to test, not permission for silent dropping in the reverse adapter. Dense incidence A_data is a scalability hypothesis only; no measured performance. Distinct from native PyPSA Network and its component tables, snapshot weights, topology, optimize model and result assignment.
- [PyPSA stochastic documentation v1.4](https://docs.pypsa.org/v1.4.0/user-guide/optimization/stochastic/) describes scenario-independent capacity variables and scenario-dependent operation, probability weighting. B converter uses PyPSA 1.3.0; C Core v1.4.0 / HEAD; Open-TYNDP 1.2.4/Linopy 0.8.0. No automatic shared environment.

## 2. Three independent interoperability paths
A native GEMS → GemsPy → Linopy solves original declarative model; already present C. This is the lowest development effort for a mathematical comparison if no PyPSA Network is required.
B restricted GEMS → native PyPSA Network: inverse of admitted library subset, not generalized algebraic inference. Need library ID + version + content hash, model ID, equation/port hash, explicit asset metadata and scenario/clock/units. Candidate only, no implementation.
C GEMS → PyPSA Network with explicit Linopy augmentation: possible for exact supported custom variables/constraints, only if reproducible augmentation and output/dual mapping accompanies Network. Network file alone insufficient; cannot simply replace n.model and claim PyPSA semantics. For arbitrary GEMS, retain native GEMS execution and translate only typed result contracts. No obligation to develop B/C if A + independent native models suffice.

## 3. Mapping specification (allowlist, not release)
Input must include study library YAML bytes/versions, component IDs, connection endpoints and master/slave fields, parameters/data groups with units/scenario/time indexing, optimizer config (time blocks, out-of-bounds, integrality, decomposition), scenario weights, target PyPSA/Linopy version and objective basis. Only fixed linear functions or expressly matched integer domains. All undefined or ignored semantics are reject-by-default. Do not use fuzzy name matching.

| Class / recognized pattern | PyPSA target | Admission and loss guard |
|---|---|---|
| energy balance bus, one carrier | Bus + explicit ENS/spill if present | resolve ports incidence signs; preserve penalties/slacks; no balancing free variable; carrier/node IDs and topology |
| fixed demand | Load | p_set and sign match; time/scenario equality; flexible service not fixed load |
| renewable/generator linear dispatch | Generator | fixed vs extendable capacity, nominal min/max, availability, marginal/investment costs, sign/emission basis; no unrepresented p_set/UC/ramp/energy budget |
| two-port activity | Link | p0=a, p1=-eta*a according to target sign; preserve bidirectionality/loss and shared rating; reject if reverse efficiency inconsistent |
| multiport fixed coefficients | Link additional ports or Process (only in target where qualified) | all outputs linked to same activity; typed carrier, capacity, coefficients and variable sign; reject general coupled polytope without exact augmentation |
| Store | Store + Link for power constraint | inventory, standing loss, time duration, charge/discharge caps, cyclic/initial/end conditions, cost, inflow/spill; no collapsing independent MW/MWh |
| StorageUnit | StorageUnit | separate charge/discharge, max_hours, efficiency and asymmetric bounds, inflow, spill; forward library p_max charging defect means original PyPSA metadata cannot be recovered in general; match actual GEMS equations or reject |
| passive line/transformer | Line/Transformer | physical x/base/tap/phase, angle gauge per AC island, KVL and modular capacity; target effective reactance reconstructible from metadata only; zero-x, inactive, PST unknown reject. Distinguish HVDC Link |
| emission/energy budget | GlobalConstraint or named Linopy constraint | exact contributions, weighting, units LHV/HHV and sign, initial/final stores, sense, coefficient; arbitrary budget not inferred |
| thermal UC | Generator/Link UC or explicit extension | discrete units vs binary, transitions, min times/ramp/initial state, costs; compare integer domains; no automatic relaxation |
| expansion & scenario tree | Core two-stage or explicit extension | capacities scenario-independent, probability normalized, CAPEX once, vintages and nonanticipativity, stage clock; Xpansion routing/decomposition never inferred from generic solution |
| arbitrary custom model | Linopy augmentation or reject | prove equality of projected feasible set and cost. Result mapping explicit. No synthetic PyPSA asset invented from LP rows alone. |

## 4. Acceptance contract and analytic counterexamples
Let source feasible set F_G, target F_P, common observable coordinates z include physical injections, activity, SOC, build, constraints, costs. Require both projected feasible sets equal under declared mapping, modulo gauge and legitimate auxiliary variables, same integrality and equivalent objective on corresponding states (explicitly account for constants). Compare exported matrices after unit/coordinate alignment, not identical row order. For general MILP full equivalence not proven by finitely many solutions; restrict to reviewed structural rules plus falsifiers. Objective-only equality not enough; degeneracy handled by checking feasibility/cost or ranges, not exact schedules unless unique. Independent evaluator recomputes residuals, state, costs. Mapping ledger: source/target identifiers, effective values, sign, clock, duration/probability, support state, transformation, data/semantic loss reason. Any relevant missing/unsupported property rejects; no silently dropped value. Structural roundtrip not byte equality; semantic roundtrip only in mutually admitted subset.

## 5. Implementation gate
Candidate reusable components: pinned GemsPy parser/study validation/AST and model builder for direct compilation; forward register/YAML as read-only mapping reference (not blindly inverted); native PyPSA API and Linopy for augmentation; B existing converter tests and A/B/C benchmarks. Need exact licenses and version environment; preserve upstream files. No reverse code, no install, no benchmark run, no commitment to implement. Decision: GEMS→Linopy exists (C); native Network reverse and augmented reverse are H/UNK, restricted feasibility contract proposed. Universal lossless inverse is refuted by non-injective forward mappings and different model semantics; existence of other implementation not ruled out.
