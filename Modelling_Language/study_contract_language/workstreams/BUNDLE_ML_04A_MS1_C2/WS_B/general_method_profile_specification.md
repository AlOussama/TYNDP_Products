# General MethodProfile — C2 research candidate
NON-NORMATIVE / RESEARCH ONLY. A profile identifies versioned mathematics by native package identity/signature, source by immutable byte digest, and its domain policies by typed input/axis roles, parameter ranges, output signature and counterfactual requirements. The mathematical rules are native expressions, not another AST. Method data are not language defaults. Source integrity is not authority authentication.
 
The executable slice uses fields id, version, native_signature, native_semantic_identity, source_ref, source_sha256, approval, input_roles, axis_roles, parameter_ranges, probability_rules, counterfactual_pairs, outputs. Study config pins the full profile, native study identity, exact data context, counterfactual context and source. Every declared method input is classified; probability rules are explicit (SUM_ONE or DEFERRED, only SUM_ONE supported in this slice). No universal probability normalization for all study weights; time weights and sample values are distinct. All methods use the same validator and native evaluator, with differing profile definitions and values. The native package provides typed units, bases and domains; method outputs must match the complete native output signature. Intermediate/output distinction still requires a contract-level binding. Exogenous context bytes are hashed and compared, pair signatures checked; project-change coverage and source authenticity require the further R1/N2R/N7 adapter.
 
Existing R1 Engine and n2r remain independent legacy/reference calculation, not canonical mathematics. The exact rational parser is reused directly. RC09 legacy mapping/validation is reexecuted as a comparison; new native path does not require the legacy translation. Existing methods with nonadmitted powers, units, ledger semantics or contexts are blocked, not approximated.
