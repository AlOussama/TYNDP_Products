# External contract language — C2 research candidate
NON-NORMATIVE / RESEARCH ONLY. Inherit the R1 N1R domain, referent, port, observable, scope, authority and variation semantics except where native predicate binding replaces the legacy mathematical expression tree. See formal_contract_semantics.md. The executable slice below validates finite complete predicate observations and outer binder order; it is not a full contract parser or a general proof engine.
 
## Abstract and concrete syntax
A StudyFrame names typed domains, study scope, chronology, information partitions, referents, observables and input/output requirements. A contract assertion is a typed record with id, semantic_role, modality, qualified native predicate reference, ordered binders, applicability guard, authority and evidence requirement. JSON records are a concrete research syntax. Native math is authored exclusively in mathspec. The role and modality are not synonyms: a prohibition is a must-not obligation, permission is not a service guarantee. Implementation-defined variation names alternatives and disclosure obligations, not arbitrary mathematical bypasses.
 
The executable subset accepts a single assertion per call with fields id, role, modality, predicate, binders, guard, authority. It uses the shared interface and C1 admitted package; no raw AST, no untyped extension. Bind every qualified predicate axis exactly once; quantifier order is explicit and independent of mathematical axis serialization. Each binder has qualified axis, domain kind, quantifier. Request-response service/capability requires FORALL request followed by EXISTS response. The finite domain is the package's admitted support, not all physically possible requests. See tests for RC01/02/03/04/05/06/07/10 bounded fragments.
 
## Reuse and remaining work
C1 Checked, bind_data, package reimport and FiniteNative are reused directly. R1 n1r.typed and C21 remain the actual legacy reference, not a second authority; their ports, observables, scope, authority, partition and disclosure checks must be integrated with qualified native references without weakening them. No claim that this integration is complete. Native data assumptions are separately typed and not external guarantees. Finite native data assumptions including where and a common group-level domain-kind registry are implemented; full guard evidence and arbitrary native conditions remain open. No universal contract conformance or owner approval.
