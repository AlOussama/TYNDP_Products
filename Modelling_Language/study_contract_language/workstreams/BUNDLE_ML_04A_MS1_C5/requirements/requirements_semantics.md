# Requirements semantics (C5 candidate 0.1)
NON-NORMATIVE / RESEARCH ONLY. OWNER_TBD.
C4 requirement design remains the authority for boundaries, data, processes, model variation, comparisons and time. The C5 research profile adds versioned requirement records, source kind (original vs research), source/authority/scope references, required/optional flag, parent derivation and external target links. SYSTEM requirements must have a parent and reference existing typed contract targets. STUDY requirements are root requirements. All parent links resolve, same scope, acyclic. Every required target must be covered by at least one test of the correct level. Many-to-many links supported within exact scope. Requirement satisfaction is a computed finite assessment, never a self-declared property. More general scope refinement, normative status delegation and external authority authentication remain open.
