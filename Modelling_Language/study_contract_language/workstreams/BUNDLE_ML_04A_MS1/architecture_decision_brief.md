# architecture decision brief

**NON-NORMATIVE / RESEARCH ONLY — MS1 — 2026-11-26**

## Decision
**OPTION F – insufficient evidence for architecture selection.** M3 (Option C) is the most promising *research hypothesis*, not approved or shown superior across original metrics. M2 is a lower-risk mapping experiment/fallback. M0 is retained. M1 is concept/syntax-only alternative if API dependency becomes unacceptable. M4/fork not justified. Neither Option E nor claim of mathspec inadequacy is supported by missing original tests.

1. Suitable candidate subset: finite parameter-only expressions, named index domains, exact arithmetic and dense sums; static conditions, ordered axes, and restricted relation/composition candidates. See S01-S20.
2. Native public parsing, Program nodes and mathematical canonical export reusable without modification on observed subset.
3. Restrict solver semantics, missing values, arithmetic domains, native masks and ordering; avoid direct use of variables as Observables.
4. Outer CSNF needs physical quantity semantics, roles, A/G/quantifiers, guards/Unknown, information, profiles, context/ledger, authority/evidence; reuse existing concepts before new language constructs.
5. Exclude variable/objective/dual for external predicate use, arbitrary Python/AST operators; defer joins/shift execution, macros/cases/full composition.
6. Potentially redundant: separate expression parser and selected mathematical index typing and normalizing logic. Not redundant yet: A/B syntax parsers, contract predicate/modal layer, physical types, CSNF semantic/audit normalizer. No deletion.
7. Native Canonical Specification can be a nested mathematical leaf; cannot replace whole CSNF. Public canonical API preferred over internal normalization.
8. Dedicated mathematical grammar unnecessary for this observed leaf scope; general necessity still open.
9. Model freedom preserved in bounded witness experiments, not proved universally.
10. External profiles swap at math layer with fixed code; complete integration not proved.
11. GEMS ports/composition and SysML/KerML typed interfaces/requirements remain concept candidates; no new native execution, SysML H0 OPEN.
12. Minimal own core not established; no new native operators justified.
13. Fundamental limits demonstrated only relative to pinned native semantics (unit/basis absence, native data/solver role, absence/guards, no authority/evidence); not impossibility of composition or extension.
14. Alpha API churn, dependency pinning, canonical hash versioning, semantic drift, exact arithmetic and wrapper maintenance.
15. No defensible full architecture rank. M3 merits bounded comparative follow-up; no MS2 release or full 04B readiness without original gates.

Review of deliverables and separate counterexamples is AI-internal, not independent human audit. Owner release and real methodology approval remain unavailable.
