# Extension and composition policy
NON-NORMATIVE / RESEARCH ONLY. Prefer data, profile and reference declarations; a new physical quantity requires registry/typed-conversion review; a new mathematical construct requires native mathspec support, typed admission and bounded consumer evidence. No custom mathematical AST or arbitrary validator extension is authorized by a profile. Preserve closed typed scopes, explicit ordered domains, source/version and evidence.

## R10 / NFR-13 — explicit typed composition
Versioned research composition request `c2-approved-composition-0.1` contains exact base digest, disjoint target slot IDs, old slot digest, complete replacement, sorted allowed native expression names. Separate externally supplied authorization root `c2-research-composition-authorization-0.1` names exact request, base, old and replacement hashes, scope, decision, source bytes and reason. Only APPROVED_RESEARCH_OVERRIDE under NON_NORMATIVE_RESEARCH_ONLY is admitted; owner remains OWNER_TBD, authenticity UNVERIFIED. This represents an explicit authorized research choice, not a claim that the actual project owner approved any decision. Production authorization would require a separately trusted real authority verification.

Replacement may change explicitly named native expressions and method identity/version/source binding within an already declared authority scope. Immutable frame, relations, sources, scopes, symbol signatures, observable projections, assertions, verification, ledger policies and native conditions/assumptions (including transitive expression bodies) are preserved. No implicit last-writer-wins, duplicate target, stale base or unapproved expression changes. Effective definition is admitted through the original validator; changed instance references must be rebound. Disjoint request order cannot change effective definition, exact raw order remains audit evidence. Envelope `c2-approved-composition-package-0.1` preserves base, request, authorization and receipt for deterministic reimport.


## Migration and rollback
Preserve historical source and audit identity; require explicit mapping of lost or unsupported concepts, report unmapped constructs, re-admit and rerun before claiming preservation. Source-coordinate research adapters may not become new study-specific primitives. C4 code changes may be reverted as commits on this research branch, never by rewriting the historic branches. Existing schemas and original oracles remain unchanged.
