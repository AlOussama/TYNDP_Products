## 2 Non-negotiable acceptance gates
**G-REQ:** 42 SLR candidate labels with original SLR01–34 unchanged, additional eight candidates justified; all derived artefacts link to source, tests, status and profile.
**G-COMP:** battery/EV/electrolyser/H2 with explicitly typed port + temporal energy/stuff/loss + service guarantee, two truly different implementations each; no physically inconsistent substitute passes.
**G-FREE:** K03+K05 must report **unnecessary forced decisions** per reference case; internal variable/count/solver/fixed algebra cannot be mandatory without a sourced physical/methodological justification.
**G-STATIC:** positive/negative tests for unknown references, unit conversion MW/MWh kg/h, sign and carrier, guard and TBD, scope/time/decision information, absence and source revision must run in an actual validator.
**G-NATIVE:** GEMS and mathspec both at documented interpreter/package versions; for identical RCs record exact source spec bytes + CLI call + expected and observed response. Existing repo tests are supporting evidence only.
**G-SEMANTIC:** multiple mathematical model structures share one outer Contract without identical algebra; trace projection/verification of required outside properties. A library-/spec-level parser cannot substitute.
**G-ROBUST:** R1–R4 kept distinct; R3/R4 require compare-ready outputs and independence declarations; different results not automatically failure, agreement not automatically true.
**G-GEN:** UC1 IoSN / UC2 N2E-CBA / UC3 network planning profile tests, with identifiable specific methodology authority. N2E authority remains open until evidence.
**G-AUTH:** Architecture options A/B/C plus "existing mathspec or GEMS with minimal extensions" must get *same* common cases. An ordinal score sum does not determine decision.
**G-GOV:** IoSN Owner D1–D6, G1 and MD/CL open state immutable through generic language research.

## 3 Controlled scientific experiment design
Recommended first two **native language slices**:
1. **RC01 Battery:** synthetically fixed values (bus ID, Δt, η, Pmax, E0/end) and two different internal energy coordinate implementations. In GEMS, produce two Libraries/identical port names and successful loading of each; in mathspec, produce two separately parsed Specs with distinct variable definitions. External rule validates both; negative leakage/balance case rejected. Full solver not required for first syntax slice; a mathematical energy witness is required for a behaviour claim.
2. **RC05 DC Network:** 3-bus triangular network with fixed susceptances, explicit line orientation, scenario and slack. Formal Angle/Cycle/PTDF equivalence with correct KVL, negative circulation (KCL passes, KVL fails). Existing numerical script is a *reference oracle*, not a native parser. Extrapolation to AC/meshed transfer limits requires independent profile.
Additional follow-on **RC03 H2 conversion**, **RC02 EV fleet** and **RC10 independently authored multimodel** establish physical multi-carrier and structural-diversity stress.

## 4 Falsifiability of architecture hypotheses
- **A Registry** fails if cross-profile joins permit inconsistent source versions, Scope/Carrier mismatch or silent obligation overrides.
- **B Integrated** fails if typed core must import concrete model variable dictionaries or has an unbounded extension/authoring burden even on simple UC2.
- **C Federated** fails if lossless semantic reconstruction requires hand-coded, undocumented data interpretation or if two views assign different owner authority to the same Rule.
- **D Existing GEMS/mathspec extended** is *supported* only if minimal extension passes same K02–K09 gates and preserved independent model structures at less cost than a separate core. Parser maturity of mathspec must not be conflated with complete Study Contracts.
- **Independent new DSL** is justified *only* if irreducible missing outer semantics plus measured adapter cost/complexity favor that path; no architecture choice is implied by this roadmap.

## 5 Evidence ledger and stop rules
At each task record `case_id, expected_property, input_sha, tool_source_sha, runtime_version, test_command, result_log, exception, evaluation_level, reviewer_independence`. Mark `NOT_EXECUTED`, `INSUFFICIENT_EVIDENCE`, `UNSUPPORTED` and `BLOCKED` separately. Parser failure due to unsupported feature does not prove physical model nonconformance; a successfully parsed syntactically malformed outer claim would indicate false-negative validation.
**Stop rules:** ambiguous required external port energy meaning; missing methodology owner/source; unreviewed assumption overrides; partial output projection falsely marked comparable; nonindependent model variants presented as independent evidence; project demands a normative decision before owner signoff. Each should block the corresponding claim but not prevent safe nonnormative language research.
