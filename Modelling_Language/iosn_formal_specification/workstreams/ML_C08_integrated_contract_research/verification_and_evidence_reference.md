## 1. Atomic test identity and result semantics

Each assertion evaluation is scoped by frozen contract/source revision, MA01-SR and property, P/M and conditional guards, tool implementation and build, model/run and generated equation instance, data instance/Y/CY/UTC/carrier/space/stage, oracle revision/tolerance/acceptance authority, V-layer and D-depth, actual attempt, evidence digests and reviewer record. A PASS for one scope never propagates automatically to another tool, changed data or version.

Exactly six individual R04/C05 outcome states:
- PASS: actually executed applicable test with complete admissible evidence and accepted oracle; property holds.
- FAIL: observed/reproducible violation of an established applicable property, not missing Owner approval alone.
- BLOCKED: source, guard, data, evidence, numeric tolerance or accepted oracle prevents judgement.
- UNSUPPORTED: independently evidenced missing required applicable tool/build capability or inspectable representation.
- NOT_EXECUTED: planned test with no completed native attempt, distinct from conceptual/synthetic self-test.
- NOT_APPLICABLE: demonstrably false legitimate conditional with frozen non-invocation witness, never a missing file.

Source/data qualification, architecture maturity, tool feature assessment, reviewer independence and G1 remain **orthogonal states**. Fail-closed D3 prohibits full PASS while required material evidence is missing, but missing evidence is not by itself scientific FAIL.
